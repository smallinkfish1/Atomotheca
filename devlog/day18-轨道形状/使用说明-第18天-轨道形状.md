# 第 18 天 · 3D s / p 轨道形状（使用说明）

> Atomotheca 模块第 4 天。目标：在 3D 场景里画出半透明的 s 球和 p 哑铃，
> 顺带把「半透明物体怎么画才不乱穿」这条渲染管线补上。

---

## 一、今日目标

1. 按 O 键，场景里出现一个半透明的 s 轨道（球）。
2. 在面板里切到 `p_x` / `p_y` / `p_z`，出现两个相切的球（哑铃），颜色分别是红 / 绿 / 蓝。
3. 用 `--dump-orbital` 在**没有显卡**的环境里核对几何：顶点数、包围盒、
   法线长度、三角形绕序。
4. 渲染管线从「一个阶段」拆成「不透明阶段 + 透明阶段」。这是今天真正的
   技术内容，轨道只是它的第一个用户。

---

## 二、核心概念

### 1. 今天画的是「角向形状」，不是「电子云」

原子轨道的完整图像是波函数 ψ(r, θ, φ) = R(r) · Y(θ, φ)。
教科书上那个漂亮的哑铃是**角向部分 Y** 的形状，不是概率密度 |ψ|²。

- `Y` 只跟方向有关，画出来就是「某个方向上能延伸多远」。
- 真正的 |ψ|² 还要乘上径向函数 R(r)，边界是模糊的（概率没有硬边界）。

今天画 `Y`，Day 20 用点云画 |ψ|²。这个区分要记住，否则会以为轨道真有那么
光滑锐利的表面。

### 2. s 是球、p 是两个相切的球——这不是近似，是精确结果

p 的角向函数正比于 cos θ（θ 从 z 轴量起），所以

```
r(θ) = |cos θ|
```

把这条曲线绕 z 轴转一圈，得到的曲面**正好**是「半径 1/2、球心在 z = ±1/2 的
两个球」。推导见《第18天实现功能原理.md》第二节，这里只记结论：

- s：一个球
- p：两个相切的球，联集看起来像哑铃

所以代码里 p 的网格就是「两次生成球、各平移 +R/2 和 −R/2」，没有任何
"长得像哑铃"的手工造型。

### 3. 半透明渲染有三条硬规则

这是今天最容易写错的地方。三条必须同时满足：

| 规则 | 不遵守会怎样 |
|---|---|
| 画在**所有不透明物体之后** | 被原子挡住的那部分轨道先写进了颜色缓冲，之后原子再画一次反而被轨道盖住 |
| 从**远到近**画 | 混合不可交换，A 叠 B ≠ B 叠 A，于是「前面那瓣被后面那瓣盖住」 |
| 关闭**深度写入**（`glDepthMask(GL_FALSE)`） | 先画的那瓣把深度写成自己的值，后画的瓣整块被深度测试剔除，看起来像少了一半 |

注意第三条只关「写」，不关「测」：深度测试要留着，这样被原子挡住的轨道
片段仍然不画。

### 为什么是 4 份网格，而不是 1 份 + 旋转矩阵

p_x / p_y / p_z 的几何完全相同，理论上可以只建一份、用三个旋转矩阵复用。
选择建 4 份的理由：

- 对称轴直接烘进顶点，渲染时不用维护「现在该乘哪个矩阵」这个隐藏状态；
- 瓣心也跟着一起烘进去，排序直接用，不需要再变换一次；
- 4 份网格一共约 4 MB 显存（2450 顶点 × 6 float × 4 字节 ≈ 59 KB，乘 4 也不到 0.3 MB），
  这个量级不值得为它引入状态。

代价是启动时多算 3 次球面（约 1 毫秒），可以忽略。

## 四、代码实现

### 4.1 一颗球怎么变成一个「瓣」

`generateSphere` 是第 3 天写的 UV 球生成器，坐标在原点、法线等于单位位置。
要把它搬到瓣心上：

```cpp
void appendSphereLobe(float lobeRadius, float cx, float cy, float cz, ShapeMesh& out)
{
    std::vector<float> verts; std::vector<unsigned int> idx;
    generateSphere(lobeRadius, kSector, kStack, verts, idx);

    const unsigned int base = static_cast<unsigned int>(out.vertices.size() / 6);

    for (std::size_t i = 0; i + 5 < verts.size(); i += 6) {
        out.vertices.push_back(verts[i + 0] + cx);   // 位置：平移
        out.vertices.push_back(verts[i + 1] + cy);
        out.vertices.push_back(verts[i + 2] + cz);
        out.vertices.push_back(verts[i + 3]);        // 法线：不动
        out.vertices.push_back(verts[i + 4]);
        out.vertices.push_back(verts[i + 5]);
    }

    for (unsigned int i : idx) out.indices.push_back(base + i);
    ...
}
```

两处容易错：

1. **`base` 必须在追加之前算**。忘了它，第二个瓣的索引会指回第一个瓣的顶点，
   渲染出来是「一个瓣加一堆飞出去的三角形」。
2. **法线不用重算**。这是均匀缩放 + 平移，方向不变。如果是非均匀缩放
   （比如把球压扁成椭球）就必须用法线矩阵，否则法线会歪。

### 4.2 p 是两瓣，各自 ±R/2

```cpp
out.lobeRadius = extent * 0.5f;
const float d  = extent * 0.5f;

float ax = 0.0f, ay = 0.0f, az = 0.0f;
switch (kind) {
    case ShapeKind::Px: ax = 1.0f; break;
    case ShapeKind::Py: ay = 1.0f; break;
    default:            az = 1.0f; break;
}

appendSphereLobe(out.lobeRadius, -ax * d, -ay * d, -az * d, out);
appendSphereLobe(out.lobeRadius,  ax * d,  ay * d,  az * d, out);
```

半径和偏心都用 `extent` 的一半，于是 p 从 −extent 伸到 +extent，
和 s 球的直径一样大。**切换 s / p 时视觉尺寸不跳**，这点很重要：
如果 p 比 s 小一圈，用户会以为「p 轨道比 s 轨道小」，那是错的印象。

### 4.3 渲染：两个阶段

原来 `renderFrame` 里原子和键是连着画的。今天把这一整段原样搬进
`drawMoleculeOpaque()`，然后在 `renderFrame` 里变成：

```cpp
if (moleculeVisible)
    drawMoleculeOpaque(view, projection, lightPos, fillLightPos, fillColor);

if (g_orbital.visible)
    drawOrbitals(view, projection, lightPos);
```

**这是纯搬家，没有改任何一行渲染逻辑**。搬的理由是：透明物体必须
「等所有不透明物体画完」再画，这个先后关系如果继续靠缩进维持，
以后加新的透明物体时迟早会插到原子前面去。

### 4.4 排序的单位是「瓣」，不是「整个形状」

p 有两瓣，一前一后。如果用整个形状的中心（原点）到相机的距离排序，
两瓣的距离永远一样，排不出先后 —— 近的那瓣仍然可能先画。

所以 `ShapeMesh` 里存了 `lobeCenters`，`drawOrbitals` 里对每一瓣单独算距离：

```cpp
for (主循环) {
    glm::vec4 w = model * vec4(centers[i], centers[i+1], centers[i+2], 1.0f);
    lobes[count].dist  = glm::length(vec3(w) - g_cameraPos);
    lobes[count].index = i / 3;
}
// 远 → 近
for (i) for (j = i+1) if (lobes[j].dist > lobes[i].dist) std::swap(lobes[i], lobes[j]);
```

只有 2 个元素，用冒泡而不是 `std::sort`：一是省掉 `<algorithm>` 的比较器，
二是**渲染循环里不允许动态分配**（架构铁律 3），而 `std::sort` 在
某些实现在小数组上也会走插入排序、不分配，但没必要赌这个。

### 4.5 一瓣分两次画：先背面，再正面

```cpp
glCullFace(GL_FRONT);   // 只留背面（远的那半张球面）
glDrawElements(GL_TRIANGLES, perLobe, GL_UNSIGNED_INT, offset);
glCullFace(GL_BACK);    // 再画正面
glDrawElements(GL_TRIANGLES, perLobe, GL_UNSIGNED_INT, offset);
```

只画正面的话，半透明的球会变成一块**扁平的色块**——因为它只剩下
对着你的那层皮。补上背面，才有「能看进内部」的层次。

配套的着色器要处理背面法线：

```glsl
vec3 N = normalize(Normal);
if (!gl_FrontFacing) N = -N;   // 背面法线朝里，翻过来才能得到正确亮度
```

### 4.6 透明度用 Fresnel，不用常数

```glsl
float facing = clamp(abs(dot(N, V)), 0.0, 1.0);
float rim    = pow(1.0 - facing, 2.5);
float alpha  = clamp(baseAlpha + rim * 0.55, 0.0, 0.95);
```

正对视线的地方最透，掠射角（轮廓）最不透明。效果是「一层壳」，
而不是「一块半透明塑料片」。`abs()` 不能省：背面法线翻过一次之后
点积符号已经变了，取绝对值才统一。

上限 0.95 也是刻意的：alpha = 1.0 就完全不透明了，等于把这个形状
最核心的「能看见内部」丢掉了。

## 六、排错清单

| 现象 | 根因 | 处理 |
|---|---|---|
| 轨道整块变成不透明 | `baseAlpha` 或 `glBlendFunc` 没设 | 确认 `glEnable(GL_BLEND)` + `GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA` |
| 轨道看起来只有一半 | 深度写入没关 | `glDepthMask(GL_FALSE)`，画完还原 |
| 前后两瓣乱穿，转视角时"跳" | 没按瓣心距离排序 | 排序单位必须是瓣（`lobeCenters`），不是整个形状的中心 |
| 轨道被原子挡住了却仍然盖住原子 | 透明阶段画在不透明阶段之前 | 顺序反过来：先 `drawMoleculeOpaque`，再 `drawOrbitals` |
| 球的内壁发黑 | 背面法线没翻 | `if (!gl_FrontFacing) N = -N;` |
| 第二瓣的三角形乱飞 | 索引偏移 `base` 没加 | 追加顶点前先取 `out.vertices.size() / 6` |
| 下一帧整个场景遮挡关系崩了 | `glDepthMask(GL_TRUE)` 忘了还原 | 透明阶段结束必须还原深度写入、关闭混合、`glCullFace(GL_BACK)` |
| `--dump-orbital` 报「绕序反了」 | 可能真的是索引绕序错 | 先看 `degenerate` 的数量：极点处 96 / 192 个退化三角形是正常的，不算错 |
| 分子隐藏后还能点到原子 | 拾取没跟着隐藏状态走 | `doPick` 里已经加了 `hideMolecule` 判断 |

## 九、遗留

1. **窗口效果未实机验证** —— 混合、排序、Fresnel 全部只做到编译级。
   需要你在真实桌面确认上面「五、窗口」列的四条。
2. **默认隐藏分子** —— `hideMolecule = true` 是刻意的：半透明轨道套在
   原子上基本看不清形状。如果你觉得切换不直观，改这一个默认值即可。
3. **p 轨道两瓣同色** —— 物理上两瓣的波函数符号相反（+ / − 相位），
   教科书常画成两种颜色。今天按「p_x 红 / p_y 绿 / p_z 蓝」的轴配色，
   没有表达相位。要表达相位就得每天再多一个开关，等 Day 19 一起考虑。
4. **没有 s / p 之外的形状** —— 那是 Day 19（d 轨道，需要真正的球谐函数）。
5. **轨道不跟随元素的价层** —— 现在是手动选形状，不是「自动显示这个元素
   最外层正在填的轨道」。后者要等 d 轨道做完，否则逻辑不完整。
