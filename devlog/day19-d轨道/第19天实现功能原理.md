# 第 19 天 · 实现功能原理（d 轨道为什么长这样）

> 面向零基础：从「l 是什么」讲到「为什么一个三角形换两个索引就能保证朝外」。
> 看懂这一篇，`--dump-orbital` 打印的每一行你都知道它在验证什么。

---

## 一、先复习一句话：我们画的是「半径 = f(方向)」

第 18 天已经确定：画的是**角向部分**，不是电子云。写法统一成

```
r(方向) = | f(方向) | × extent
```

`f` 是球谐函数（的一个常数倍），`extent` 只是整体缩放，让它跟分子大小匹配。
于是「画出轨道」这件事就变成「把每个方向的半径算出来，再把点连成三角形」。

| 轨道 | f | 瓣尖半径 |
|---|---|---|
| s | 1 | extent（球） |
| p | 沿自己轴的坐标分量 | extent |
| d | 见第三节 | extent |

之所以全都能写成「半径 = 函数(方向)」，是因为 f 只跟方向有关、跟远近无关
（球谐函数是球面上的函数）。这类曲面叫 **星形曲面**：从原点出发的每条射线，
跟曲面只交于一点。

---

## 二、l 是什么：节面的个数

量子数 `l` 决定角向函数的「角向复杂度」，而复杂度有一个可数的指标：**节面数 = l**。

「节面」就是 f = 0 的地方。在 `r = |f|` 的画法里，节面上半径是 0，
整个曲面在那里被捏成一个点。所以：

- `l = 0`（s）：f 是常数，永远不为 0 → 没有节面 → 一个球。
- `l = 1`（p）：f 在某个平面（比如 x-y 平面）上为 0 → 一个节面 → 曲面被切成两半，
  每半是个球，合起来是哑铃。
- `l = 2`（d）：f 在两个地方为 0 → 两个节面 → 曲面被切成四块（四瓣梅花），
  或者两瓣加一圈腰环（`d_z2`）。

这就是「p 有 3 个轨道、d 有 5 个、f 有 7 个」的几何来源：
l 越大，能把 f 摆成的独立朝向越多，个数是 `2l + 1`。

| l | 轨道数 2l+1 | 节面数 l |
|---|---|---|
| 0 | 1（s） | 0 |
| 1 | 3（p_x, p_y, p_z） | 1 |
| 2 | 5（d 的五个） | 2 |
| 3 | 7（f） | 3 |

## 三、五个 d 到底长什么样：从球坐标推到直角坐标

球谐函数的标准形式是写成极角 θ、方位角 φ 的函数。l = 2 的五个（实数形式）是：

| 名字 | 球坐标形式（差一个常数） | 直角坐标形式（r = 1） |
|---|---|---|
| `d_z2` | `3cos²θ − 1` | `3z² − 1` |
| `d_xz` | `sinθ cosθ cosφ` | `xz` |
| `d_yz` | `sinθ cosθ sinφ` | `yz` |
| `d_xy` | `sin²θ sin2φ` | `2xy` |
| `d_x2-y2` | `sin²θ cos2φ` | `x² − y²` |

怎么换的？只用三条关系（单位球上 `x² + y² + z² = 1`）：

```
x = sinθ cosφ       y = sinθ sinφ       z = cosθ
sin2φ = 2 sinφ cosφ        cos2φ = cos²φ − sin²φ
```

举个例子，`d_xy`：

```
sin²θ sin2φ = sin²θ · 2 sinφ cosφ
            = 2 · (sinθ cosφ) · (sinθ sinφ)
            = 2xy
```

`d_x2-y2` 同理：

```
sin²θ cos2φ = sin²θ (cos²φ − sin²φ) = (sinθcosφ)² − (sinθsinφ)² = x² − y²
```

最后乘常数把「最大值」归一到 1（这样所有形状的瓣尖都在 `extent` 上，切换时不跳）：

- `2xy` 的最大值：`x = y = 1/√2` 时 `2 × 1/2 = 1` ✓
- `x² − y²` 的最大值：`x = 1, y = 0` 时 `1` ✓
- `(3z² − 1)/2` 的最大值：`z = 1` 时 `(3−1)/2 = 1` ✓

**这一步不是数学游戏**：它解释了「为什么 `d_xy` 的瓣在对角线上」——
`2xy` 在 `x = y` 的方向上最大，那个方向就是 45°。同理 `d_x2-y2` 的瓣在坐标轴上。
两者其实是同一个形状转了 45°，所以它们的体积必须相同（实测都是 0.8127）。

## 四、`d_z2` 为什么多出一个「腰环」

`f = (3z² − 1)/2`，令 f = 0：

```
3z² = 1  →  z = ±1/√3 ≈ ±0.577
```

注意这不是「z 等于某个数的平面」，而是「z/r 等于 0.577 的**圆锥面**」。
球坐标里 `z = cosθ`，所以 `cosθ = ±1/√3` 对应 **θ = 54.7° 和 125.3°**。
化学里 54.7° 有个名字叫魔角（magic angle），核磁共振里天天见。

于是曲面被两个圆锥面切成三块：

| 区域 | f 的符号 | 半径变化 |
|---|---|---|
| 北极附近（θ < 54.7°） | 正 | 0 → 1（大瓣） |
| 赤道带（54.7° < θ < 125.3°） | 负 | 0 → 0.5 → 0（腰环，半径只有大瓣的一半） |
| 南极附近 | 正 | 0 → 1（大瓣） |

所以 `d_z2` 的剖面是「大瓣、细腰、小裙、细腰、大瓣」。这就是它和另外四个
看起来完全不同的原因：另外四个的节面是**平面**（把空间切成四块相等的部分），
`d_z2` 的节面是**圆锥面**（把空间切成「两极 + 赤道带」三块）。

> 顺便回答一个常见疑问：为什么 `d_z2` 不叫 `d_z²` 而写成 `d_z2`？
> 因为 ImGui 的默认字体只有 ASCII，`²` 会渲染成方块。名字是给程序用的，
> 公式在面板里另有一行 `r = |3z^2-1|/2`。

## 五、怎么把球面变成 d 形状

思路只有一步：**改半径**。

```
对每个方向 d̂ = (sinθcosφ, sinθsinφ, cosθ)：
    r = |f(d̂)| × extent
    顶点位置 = d̂ × r
```

球面是 `r = 常数`，d 形状是 `r = 随时间变化`。三角形怎么连、索引怎么排，
跟生成球体一模一样——变的只有顶点位置。

分段数从 48×24 提到 96×48，原因是 d 的形状在角向变化更剧烈：
48 段时一个瓣只有 12 段经线，瓣的边缘会出现肉眼可见的折线。
96 段时一个瓣有 24 段，看起来才像光滑曲面。

代价是三角形数从 2304 涨到 9216。五个 d 一共 46k，仍然远小于一颗原子球的负担
（原子球是 32×16，但分子里可能有几十颗）。

## 六、法线：不用求导，用「隐函数梯度」

半透明轨道着色要用到法线（Fresnel 项靠它算边缘亮度）。球面的法线就是位置方向，
但 d 形状的法线不能这么偷懒。

### 常规做法为什么麻烦

理论上可以对参数方程 `S(θ, φ)` 求两个偏导再叉乘：

```
n ∝ ∂S/∂θ × ∂S/∂φ
```

问题是：`r` 里含有 `|f|`，在节面附近 `r → 0`，`∂S/∂φ` 也趋近 0，
叉积变成 0/0；而且五个形状要写五套导数，写错一个只有肉眼能发现。

### 更省事的做法

把曲面写成**隐函数**：

```
F(p) = |p| − f(p̂) · extent = 0
```

曲面上每个点都满足 F = 0。而微积分里有个结论：

> **梯度 ∇F 垂直于等值面，并且指向 F 增大的方向。**

曲面内侧 `|p|` 更小 → F 更小；外侧 F 更大。所以 **∇F 就是朝外的法线**，
归一化一下就能用。

### 梯度怎么算：差分

`∇F = (∂F/∂x, ∂F/∂y, ∂F/∂z)`。对代码来说，连解析求导都不用：

```
∂F/∂x ≈ [F(x+h, y, z) − F(x−h, y, z)] / (2h)
```

这就是**中心差分**：取左右各一点点，看 F 变了多少。六个采样点换掉一整套解析推导。

`h` 的取法有讲究：`extent/1000`。太大（比如 0.1）会把曲面细节抹平，
算出来的法线像被磨过；太小（比如 1e-9）会被 float 的精度吃掉，两个 F 值一模一样，
差分成 0。取 0.001 是这类问题的常用经验值。

## 七、绕序：为什么「换两个索引」就能保证朝外

### 绕序是什么

三角形有三个顶点，按索引顺序绕一圈，有两个可能的方向：顺时针（CW）和逆时针（CCW）。
OpenGL 用 `glFrontFace(GL_CCW)` 认定「从外面看逆时针的那一面是正面」，
然后 `glCullFace` 据此决定剔哪一面。

写反了的后果很具体：你会看到球的内壁——没有明暗渐变、前后遮挡全乱。

### 为什么变形之后会反

UV 球面上，固定的索引顺序能保证「从外看逆时针」。但颜色变了形状也变了：
d 的曲面在节面附近是**翻折**的（半径先减到 0 再涨回来），
在那里，同一套索引顺序算出来的叉积方向会翻过来。

### 解决办法：让程序自己判

三角形的几何法线是边的叉积 `g = e1 × e2`；顶点法线（第六节算的）都朝外，
所以三个顶点法线之和 `sn` 也朝外。于是：

```
如果 dot(g, sn) < 0，说明这个三角形是「从里往外看逆时针」的
→ 把索引 b 和 e 换个位置，方向就反过来了
```

一行判断，胜过五套手写的索引表。这也是为什么 `--dump-orbital` 里
`winding: 0 / 9216 triangles reversed` 值得看：它验证的是「这条断言对每个三角形都成立」。

## 八、体积校验：为什么它能抓到我算错的常数

### 散度定理（零基础版）

一个封闭曲面围出的体积，可以用曲面上每一点的位置和法线积分出来：

```
V = (1/3) ∮ p · n dA
```

关键点：**这个公式跟原点在哪无关**。哪怕曲面不在原点周围（比如 p 的两个相切球，
一个在 +z 一个在 −z），积分出来的仍然是它围住的总体积。

三角形化之后，每个三角形贡献一项：

```
V += (1/6) · p0 · (p1 × p2)        ← 混合积
```

混合积 `p0 · (p1 × p2)` 的几何意义是「原点、p0、p1、p2 四点围成的六面体体积的 6 倍」，
所以除以 6 就是那个四面体的体积。把整个曲面上的四面体加起来，就是总体积。

**方向很关键**：三角形朝外时贡献为正，朝里时为负。所以如果绕序整体反了，
算出来的体积会变成**负数**。

### 为什么这条校验特别值钱

法线是第七节算出来的，绕序又是用几何法线和顶点法线比出来的——
「用法线验绕序、用绕序验法线」等于自己证明自己。体积不一样：
它只从三角形的位置和顺序积分，和法线**完全无关**。

这就是它今天当场抓到错的原因：

我手写了 `p` 的解析体积，写成了 `πR³/6`。正确的算法是：

```
两个半径 R/2 的球：
V = 2 × (4/3)π(R/2)³ = 2 × (4/3)π · R³/8 = πR³/3
```

少乘了一个 2。运行 `--dump-orbital` 立刻看到 `198.6%`——正好差 2 倍，
一眼就知道是常数写错，不是几何写错。改对后三个 p 全是 99.3%。

> 教训：**校验要选和被测对象不共享假设的量**。
> 网格是内接多面体，永远比真实曲面小一点点，所以 98%~99% 是正常的；
> 一旦看到 198% 这种整齐倍数，先怀疑自己的公式，别怀疑网格。

## 九、分瓣：为什么 d 的「每瓣三角形数」不一样

半透明渲染要求从远到近画，而排序的单位是**瓣**（第 18 天已经踩过这个坑：
用整个形状的中心排序，p 的两瓣距离永远相同，等于没排）。

所以网格要能回答「第 k 瓣的三角形在索引数组的哪一段」。s / p 里每瓣都是一个
一模一样的球，用「总长 ÷ 瓣数」就能算出来。d 不行：

| 形状 | 每瓣三角形数 | 为什么不等 |
|---|---|---|
| `d_xy` | 2310 / 2302 / 2302 / 2302 | 四瓣大小相同，只是网格边界压线不同 |
| `d_z2` | 2016 / 2016 / **5184** | 腰环是整条赤道带，包了大半圈经线 |

于是 `ShapeMesh` 加了 `lobeFirst / lobeSize` 两个数组，渲染时查表取偏移量。
这不是「多写一行代码」的事——用错的话画面上是**几个瓣拼错位置**，
比整块消失更难查，因为你会以为是自己看错了。

### 分瓣的依据：最近的瓣心

程序怎么知道一个三角形属于哪一瓣？算它的重心，看离哪个瓣心最近。

- 四瓣梅花：瓣心在对角线上（`(±1,±1,0)/√2 × 0.55·extent`）。
- `d_z2`：两极各一个，**腰环的瓣心是原点**。

腰环取原点是刻意的：排序时原点的深度正好落在两极之间，
于是绘制顺序是「远瓣 → 腰环 → 近瓣」，腰环被夹在中间——和肉眼看到的一致。

## 十、这一天的三个「一句话总结」

1. **形状**：所有轨道都是 `r = |f(方向)| × extent`，l 决定节面数，f 的具体形式
   决定了瓣朝哪摆。`d_z2` 特别，只是因为它的节面是圆锥不是平面。
2. **法线**：把曲面写成 `F(p) = |p| − f(p̂)·extent = 0`，∇F 就是朝外法线，
   差分算梯度，永远不用除零。
3. **校验**：法线和绕序互相自证没有意义，所以再加一条体积（散度定理）——
   它今天当场抓到了一个「差 2 倍」的公式错误。
