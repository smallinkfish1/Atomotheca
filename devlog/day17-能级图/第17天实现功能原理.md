# 第 17 天实现功能原理

> 面向"能看懂 C++、但化学和图形都是新手"的读者。
> 目标不是复述代码，而是讲清楚每一步**为什么必须这样**。

## 一、能级图到底在画什么

一张能级图上，每个小方框代表**一个轨道**，方框里的箭头代表**一个电子**。

它回答三个问题：

1. 电子住在哪些层？（s / p / d）
2. 每层住几个？（2p⁴ 还是 2p⁶）
3. 同一层里怎么分？（三个框各一个 ↑，还是一个框 ↑↓ 加一个空框）

它**不**回答的问题是：「这个电子的能量是 −24.6 eV 还是 −8.9 eV」。图上纵向只有次序，没有刻度。

### 为什么不画刻度

要画真实能量，得给每个元素单独算一套数值。而轨道能量不是固定的：

- 同一个 3d，在 Sc 里和在 Zn 里能量不一样（核电荷从 +21 涨到 +30）；
- 电子的能量还受其它电子屏蔽影响，改一个电子全部重算。

这是量子化学计算（Hartree-Fock / DFT）的活。本项目是教学工具，做的是「**次序**」——而学生需要记住的恰好也是次序。

## 二、次序是怎么定出来的

### 2.1 三个量子数决定了"住在哪"

| 符号 | 名字 | 取值 | 决定 |
|---|---|---|---|
| n | 主量子数 | 1, 2, 3… | 第几层（越大越远、能量越高） |
| l | 角量子数 | 0=s, 1=p, 2=d, 3=f | 这一层的形状 |
| m | 磁量子数 | −l … +l | 这一层里有几个轨道 = 2l+1 |

所以：

- s（l=0）→ 1 个轨道 → 最多 2 个电子
- p（l=1）→ 3 个轨道 → 最多 6 个
- d（l=2）→ 5 个轨道 → 最多 10 个
- f（l=3）→ 7 个轨道 → 最多 14 个

这条叫 **泡利不相容原理** 的推论：一个轨道最多两个电子，且自旋相反。所以容量 = 2×(2l+1)，代码里就是：

```cpp
int subshellCapacity(int l) { return 2 * (2 * l + 1); }
```

### 2.2 先后顺序：`n + l` 小的先填

Madelung 规则（也叫 Klechkowski 规则），两条：

1. **n+l 小的能量低，先填**；
2. **n+l 相同，n 小的先填**。

算一遍就明白为什么 4s 在前：

| 亚层 | n | l | n+l | 名次 |
|---|---|---|---|---|
| 3p | 3 | 1 | 4 | 早 |
| **4s** | 4 | 0 | **4** | 早（n=4 但和 3p 同分，n 比 3d 小）|
| **3d** | 3 | 2 | **5** | 晚 |
| 4p | 4 | 1 | 5 | 晚 |

4s 的 n+l=4，3d 的 n+l=5，所以 4s 先。**不是"4 比 3 大所以后填"** —— 这是初学者最容易搞反的地方。

代码里就是这么排的（`sortByEnergy`）：

```cpp
const int sa = a.n + a.l;
const int sb = b.n + b.l;
if (sa != sb) return sa < sb;   // 先比 n+l
return a.n < b.n;               // 同分时 n 小的先
```

### 2.3 一个反直觉的事实：Sc 之后 3d 比 4s 低

严格来说，Madelung 规则描述的是**填充时的顺序**，不是原子稳定后的能量高低。

- K、Ca（Z=19、20）：4s 确实低于 3d，电子进 4s。
- **Sc 之后（Z≥21）**：核电荷继续增加，3d 轨道收缩得比 4s 快，能量反过来低于 4s。

那为什么 Fe 的排布式还写 `3d⁶ 4s²`，而不是 `3d⁸`？

因为**填充顺序**决定了电子怎么分配：先把 4s 填满，再填 3d。填完之后即使 3d 能量更低，电子也不会自己"跳"过去 —— 那需要额外的能量，而且跳过去还得有两个电子挤进同一个轨道（违反泡利），不划算。

这个细节解释了今天这张图最重要的一个用途：

> **Fe²⁺ 为什么是 3d⁶ 而不是 3d⁴4s²？**
> 因为 4s 是最外层，电离时先丢最外层的电子。所以 `--dump-levels Fe` 里，Fe²⁺ 的 4s 显示 `0/2`（空了），3d 仍然是 `6/10`。

能级图上 4s 画在 3d 下面，正好把"4s 先被填、也先被夺走"这件事画出来了。

## 三、方框里怎么摆箭头

### 3.1 洪特规则

同一亚层里，电子**先各占一个轨道、自旋平行**，占满才配对。

三个 p 轨道、4 个电子：

```
错误：  [↑↓] [  ] [  ]     能量偏高
正确：  [↑↓] [↑ ] [↑ ]
```

为什么？两个原因（都是量子力学的结论，不是"电子互相讨厌"这么口语化）：

- **交换能**：自旋平行的电子交换位置时波函数不变号，这种"交换"降低能量。平行自旋越多，交换能越低。
- **屏蔽与平均距离**：分占不同轨道，电子平均距离更远，排斥更小。

### 3.2 用两个整数描述整个画面

直觉写法是给每个轨道存 0/1/2：

```cpp
std::vector<int> perOrbital;   // 5 个 d 轨道 → {2, 1, 1, 1, 1}
```

但洪特规则让分布**唯一确定**，所以只要知道「有几对」，剩下的信息全是废的：

```
k 个轨道，n 个电子：
  paired = max(0, n - k)     // 超出轨道数的电子只能配对
  single = n - 2 * paired    // 其余轨道各一个
```

验算 `3d⁶`：k=5, n=6 → paired = max(0,1) = 1，single = 6-2 = 4。
画面：`[↑↓][↑][↑][↑][↑]` —— 一对 + 四个单占，和课本一致。

验算 `2p³`：k=3, n=3 → paired = 0，single = 3 → `[↑][↑][↑]`。

这个推导省掉了整个 vector，也让「同一亚层内的分布」不依赖任何顺序 —— 五个 d 轨道是简并的，画哪个成对都等价。

### 3.3 箭头为什么必须自己画

ImGui 默认字体是 ProggyClean，只含 ASCII。`"↑"`（U+2191）不在字形表里，渲染出来是个空方块 —— 和中文名显示成 `??` 是同一个根因。

所以箭头是画出来的：

```cpp
// 一根竖线 + 顶端一个实心三角
dl->AddLine(base, tip, color, 1.6f);
dl->AddTriangleFilled(tip, 左底角, 右底角, color);
```

「↑ 靠左、↓ 靠右」并排放，就是一对自旋相反的电子。

颜色上，↑ 用蓝（65,132,220）、↓ 用橙（224,112,64）。选这两种是因为它们在深色背景上对比都够，而且红绿色盲也能区分（蓝-橙比红-绿安全）。

## 四、ImGui 里画这张图的三个坑

### 4.1 状态必须跨帧存活

能级图每帧重画。如果 `rows` 是绘制函数的局部变量，每帧都要重建一次 —— 一秒 60 次，每次复制几个 vector。

所以状态放在 `EnergyDiagramState` 里，并且加两层缓存键：

```cpp
if (cachedZ == element.atomicNumber && cachedCharge == charge) return;
```

只有「换元素」或「换离子」时才重算。这是响应式 UI 的常见模式：**渲染是每帧的，数据不是**。

### 4.2 一块画布 + 坐标反算

45 个方框，如果每个都做成一个 `InvisibleButton`：

- 45 个 ID 必须唯一（Day 16 的坑：共用 ID 会"点一格亮另一格"）；
- 45 次布局计算，只为了一句 tooltip。

改成整块区域一个按钮，鼠标落在哪一行用**除法**算：

```cpp
const int fromTop  = (int)((mouse.y - canvasPos.y) / kRowH);
const int hoverRow = rowCount - 1 - fromTop;
```

为什么能这么算：行高是常量 `kRowH`，行与行严格等距，所以 `y` 除以行高就是行号。而 `rows[0]`（最低能量）画在最下面，所以行号要倒过来。

**代价**：如果以后做成"行高可变"（比如按 n+l 差值给不同间距），这个除法就不成立了，得改成遍历。现在不做，写在这里备忘。

### 4.3 窗口宽度不能靠猜

`ImGui::TextDisabled` **不会自动折行**。窗口宽度算少了，文字直接被裁掉半句，而且没有任何警告。

宽度由三块拼成：

```
亚层标签列 38 + 5 个方框 100 + 右侧计数 80 = 218，再加左右内边距 24
```

第一版右侧只留了 64，结果图例最后一行 `follows the periodic table selection` 超宽被切。这类问题在没有 GL 上下文的环境里看不出来，只能靠"算过一遍"和用户实机反馈。

## 五、为什么还要一个 ASCII 版

`--dump-levels` 打的不是"另一份实现"，而是**同一份 `rows`** 的文本渲染：

```
  3d     [^v][^ ][^ ][^ ][^ ]  6/10
  4s     [^v]                  2/2
```

它存在的理由和 `--dump-table` 一样：这个开发环境没有 GL 上下文，窗口开不起来，但「4s 在 3d 下面」是纯数据结论，用终端就能核对。

而且它抓到了一个真实的 bug：第一版在 Fe 的 3d 未满时就标了「4p 待填」。这个错误在界面上完全看不出来（空框看起来很正常），只有在文本里读到 `4p 0/6 (next to fill)` 才觉得不对劲。

> 一个可验证的输出通道，比"我看了一遍界面觉得没问题"可靠得多。

## 六、今天没做的事，以及为什么

| 没做 | 原因 | 什么时候做 |
|---|---|---|
| 绝对能量刻度 | 需要每个元素一套量子化学计算，超出项目范围 | 不做 |
| 完整 7 周期全景 | 数据只到 Kr；画满会全是空框 | 补 5–7 周期时 |
| 能级图里的元素切换 | 会和周期表形成两个"当前选择" | 不做，改成跟随 |
| 键盘上下键换元素 | 需求不明确，鼠标点周期表更快 | 看用户反馈 |
| 浅色主题 | 应用固定深色（3D 查看器的常见选择） | 需要时再加 |
| 元素中文名 | ImGui 默认字体无中文字形 | 与 Day 16 一起做字体方案 |

**范围控制的原则**：今天只做"把已有的电子数据画成能级图"。可以顺手加的东西（切换元素、动画、能量刻度）每一样都会引入新的状态或新的依赖，一旦出问题就分不清是哪个改动引起的。
