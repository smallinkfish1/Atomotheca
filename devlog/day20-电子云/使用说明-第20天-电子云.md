## 二、核心概念

### 1. 为什么概率要乘 r²

球坐标的体积元是

```text
dV = r² sinθ · dr dθ dφ
```

所以「电子落在半径 `r` 到 `r+dr` 这层球壳里」的概率是

```text
P(r)dr = r² · R²(r) · dr · ∫|Y|²dΩ = r² R²(r) dr
```

**`R²` 在原点最大，但 `P(r)` 在原点等于 0** —— 因为原点的球壳面积是 0。
这件事决定了电子云长什么样：`1s` 最密的地方不是原子核，而是 `r = a₀`。
如果漏掉这个 `r²`，每个轨道都会变成一个中心极亮的点，怎么调参数都不对。

### 2. `|ψ|²` 是可分离的，所以两块能分别精确抽

```text
|ψ|² = R²(r) · |Y(方向)|²
```

- 对**方向**积分掉之后，半径的边缘分布是 `P(r) = r²R²(r)`；
- 对**半径**积分掉之后，方向的边缘分布是 `|Y(方向)|²`（因为 `∫r²R²dr = 1`）。

两者独立，于是可以「先抽半径，再抽方向」，各用各的方法。这一步不是技巧，
是这道题本身的性质。

### 3. 为什么不在立方体里直接拒绝

直觉做法：在边长为 `2rMax` 的立方体里均匀撒点，密度够大就留下。
算一下接受率：`1s` 的 `ρ` 峰值是 `1/π ≈ 0.318 a₀⁻³`，`rMax ≈ 4 a₀`，立方体体积 `512 a₀³`。
接受率 ≈ `1 / (0.318 × 512) ≈ 0.6%` —— 6 万个点要试一千万次。
`3d`、`6s` 更糟（峰值更低、盒子更大）。

改成「反演径向 CDF + 球面拒绝」之后：

| 角向 | 球面拒绝的接受率 | 实测尝试次数/点 |
|---|---|---|
| s | 100% | 1.01 |
| p | 33% | 3.04 |
| d_z2（最差） | 20% | 5.02 |

径向那一步是**精确反演**，没有拒绝，一次 12 次二分比较。
所以 20 万个点也就几十毫秒。

### 4. 径向节面数 = n − l − 1

| 轨道 | 节面数 | 位置（a₀） |
|---|---|---|
| 1s | 0 | — |
| 2s | 1 | 2.00 |
| 3s | 2 | 1.90, 7.10 |
| 3p | 1 | — |
| 3d | 0 | — |
| 6s | 5 | 1.85, 6.34, 13.83, 25.20, 42.78 |

这就是「2s 是两个球套在一起、1s 只有一个球」的全部原因。
`--dump-cloud 3s` 的一维剖面里能直接数出两个零。

### 5. 每个点的透明度必须是常数

点的**数量密度**已经正比于 `ρ` 了。如果每个点再乘一次 `ρ` 当亮度，
等于把概率密度**平方**了一次：中心会糊成死白，壳层和节面全部消失。

所以：`点数/体积 ∝ ρ`（采样保证），`单点 alpha = 常数`（着色器保证）。
层次是「一屏上多少点重叠」自然堆出来的，不是手调的。

### 6. 相位染色：颜色表达符号，不表达正负电荷

同一个轨道的相邻瓣，波函数符号相反（`+ / −`）。染色之后：

- `2p_z` 上下两瓣一红一蓝；
- `3s` 三层壳红蓝红交替；
- `3d_xy` 四个瓣按对角线交替。

节面不用画线，它自己就是颜色分界。

## 三、架构

### 新文件，还是那条分层线

```text
src/orbital/cloud.h     102 行  量子数、点、统计量、采样接口（纯数学）
src/orbital/cloud.cpp   777 行  径向函数 + 球谐 + CDF 反演 + 拒绝采样 + 自检 + ASCII
src/ui/cloud_panel.h     47 行  面板状态
src/ui/cloud_panel.cpp   88 行  折叠区控件（不自带 Begin/End）
src/shaders/cloud.vert   35 行  透视点径
src/shaders/cloud.frag   37 行  圆盘软边 + 相位两色
```

- `orbital/cloud.*` **不 include `<glad/glad.h>`**，和 `element.*`、`shape.*` 一个规矩。
  它可以被 `--dump-cloud` 单独调用，在没有显卡的环境里跑出全部结论。
- 面板只改状态，不建缓冲；建 VBO、开混合、画点都在 `main.cpp`。
- 复用 `orbital::ShapeKind` 当「角向部分」的选择，没有另造一套枚举 ——
  昨天的九个角向函数和今天的球谐是同一份数学，只是昨天丢掉了符号和径向。

### 渲染从两阶段变三阶段

```text
不透明（原子、键）  →  点云  →  半透明外壳（s/p/d 形状）
```

点云排在中间：外壳是「包在外面的壳」，让它压在云上面更符合直觉；
而点云必须在原子之后画，否则被原子挡住的部分会先写进颜色缓冲。

### 为什么要缓存「已上传的那一套量子数」

`AppState` 里存了 `cloudBuiltN / cloudBuiltKind / cloudBuiltPointCount / cloudBuiltSeed`。
每帧只比这四个标量，不一致才重新采样。比的是四个数而不是几十万个坐标 ——
逐字节比较点坐标比重新采样还慢。

## 四、代码实现

### 4.1 径向函数：连带拉盖尔多项式

```cpp
R_nl(r) = sqrt( (2/n)³ · (n−l−1)! / (2n·(n+l)!) )
          · e^(−r/n) · (2r/n)^l · L^(2l+1)_(n−l−1)(2r/n)
```

`L` 用三项递推算，不展开系数：

```cpp
double laguerre(int k, int alpha, double x)
{
    if (k <= 0) return 1.0;
    double lm1 = 1.0;                  // L_0
    double l   = 1.0 + alpha - x;      // L_1
    for (int i = 1; i < k; ++i) {
        const double next = ((2.0*i + 1.0 + alpha - x) * l - (i + alpha) * lm1) / (i + 1);
        lm1 = l;
        l   = next;
    }
    return l;
}
```

`n = 6` 时展开系数是五位数的分数，手写必错；递推只有一行。

### 4.2 球面：九个实球谐，带符号

和 Day 19 的 `shape.cpp` 是同一套式子，区别只有两个：
**归一化系数**（昨天可以随便乘，因为只看形状）和**符号**（今天要染色）。

```cpp
static const double kS  = 0.5 / sqrt(kPi);                 // l = 0
static const double kP1 = sqrt(3.0 / (4.0*kPi));           // l = 1
static const double kD2 = sqrt(15.0 / (4.0*kPi));          // d_xy / d_yz / d_xz
static const double kD3 = sqrt(15.0 / (16.0*kPi));         // d_x2-y2
static const double kD4 = sqrt(5.0 / (16.0*kPi));          // d_z2
```

这五个常数不是抄的，是按 `∫|Y|²dΩ = 1` 解出来的。验算方式：
`⟨cos²θ⟩` 的样本值必须等于球面积分值（见 4.5）。

### 4.3 径向 CDF：把连续分布压成 4096 格

```cpp
dr = rMax / bins;
cdf[i] = cdf[i-1] + 0.5 * (density(r_{i-1}) + density(r_i)) * dr;   // 梯形
```

反演时二分找格子，再在格子内线性插值：

```cpp
int i = 第一个 cdf[i] > u 的格子;
double f = (u - cdf[i-1]) / (cdf[i] - cdf[i-1]);
return (i - 1 + f) * dr;
```

`rMax` 从 `20n + 10` 起，如果尾部概率还大于 `1e-9` 就 ×1.5 重来。
判据用了一个保守上界：`p(r)` 过峰值之后按 `e^(−2r/n)` 衰减，
所以尾部积分 ≈ `p(rMax)·n/2`，再乘上多项式因子的余量取 `p(rMax)·(n+2)`。

实测截尾概率：`1s` 是 `9.5e-23`，`3d_z2` 是 `2.6e-13`，`6s` 是 `3.2e-13`。可以当它是 0。

### 4.4 方向：拒绝采样的上界不能靠猜

```cpp
const AngularProbe probe = probeAngular(kind);     // 600×600 网格扫描
const double yMax2 = probe.maxSquared * 1.01;      // 网格不会正巧落在峰顶，留 1%
```

**上界偏大只是多拒几次，偏小会悄悄截断分布** —— 而截断在图上完全看不出来
（形状还是对的，只是瓣尖被削平了一点点）。所以这里不能「差不多就行」，
而且必须有 `⟨cos²θ⟩` 这样的独立量来兜底。

同理，`AngularProbe::maxSquared` 的初值必须是 `0.0` 而不是 `1.0`：
`|Y|²` 的峰值只有 0.08 ~ 0.40，从 1.0 起扫会让上界虚高十几倍，
接受率掉到 1/13（这个 bug 是我自己写出来的，见第六节）。

### 4.5 四类自检，各自不共享假设

| 量 | 样本值 | 对照 | 能抓到什么 |
|---|---|---|---|
| `⟨r⟩` | 平均撒出来的半径 | `(3n² − l(l+1))/2` | 径向函数、CDF、反演，全链路 |
| `⟨r²⟩` | 同上 | `n²(5n²+1−3l(l+1))/2` | 同上，对尾部更敏感 |
| `⟨cos²θ⟩` | 采样方向的 `z²` 均值 | 600×600 网格积 `|Y|²` | 球谐系数、上界、拒绝逻辑 |
| KS 偏差 | 经验 CDF vs 查表 CDF | `1.36/√N` | 反演是否无偏 |

`⟨r⟩` 和 `⟨r²⟩` 是**闭式解**，从 `|ψ|²` 直接积出来，和采样流程没有共同假设；
`⟨cos²θ⟩` 与径向完全无关。所以这四条不是互相印证，是各自独立对账。

### 4.6 渲染

顶点着色器只多了一行：

```glsl
float dist = max(length(vec3(world) - viewPos), 0.001);
gl_PointSize = clamp(pointSizeWorld * sizeScale / dist, 1.0, 48.0);
```

`sizeScale = (视口高/2) / tan(fov/2)`，在 CPU 上算一次。
**视口高要用 `glfwGetFramebufferSize`**，不是窗口高度 —— HiDPI 屏上两者差一倍，
用窗口高度会让 Retina 上的点小一半。

片段着色器把方点裁成圆：

```glsl
vec2 d = gl_PointCoord * 2.0 - 1.0;
if (dot(d, d) > 1.0) discard;
```

Core Profile 下 `gl_PointSize` **默认不生效**，必须 `glEnable(GL_PROGRAM_POINT_SIZE)`。
漏了它的症状很典型：所有点都是 1 像素，整朵云像一层噪点。

混合策略和三角形完全不同：

```text
深度测试：开（被原子挡住的点不画）
深度写入：关（点与点不互相遮挡）
排序    ：不做 —— 几十万个点排不动
```

单点 alpha 低、点又小，所以顺序差异肉眼看不出来。这是点云和三角面片在
混合策略上的根本区别，不是偷懒。

### 4.7 尺寸归一：比的是形状，不是大小

不同 `n` 的真实半径差好几倍（`1s` 的 r98 = 3.8 a₀，`6s` 是 84.4 a₀）。
如果按真实比例画，`1s` 会变成一个像素点。所以渲染按 r98 归一到
`分子半径 × 1.7`，而**真实半径写在面板上**（`mean r … a0   r98 … a0`）。

## 六、排错清单

| 现象 | 原因 | 处理 |
|---|---|---|
| 所有点都是 1 像素，像一层噪点 | Core Profile 里没开 `GL_PROGRAM_POINT_SIZE` | 启动时 `glEnable`，一次就够 |
| HiDPI 屏上点小一半 | 用 `glfwGetWindowSize` 算 `sizeScale` | 改用 `glfwGetFramebufferSize` |
| 点全是方块 | 片段着色器没按 `gl_PointCoord` 裁圆 | `r² > 1` 时 `discard` |
| 中心糊成死白，看不见壳层 | 单点 alpha 乘了密度（等于把 ρ 平方） | 单点 alpha 必须是常数 |
| 1s / 2s / 3s 长得一模一样 | 只用了 `|Y|`，没乘 `R_nl` | 检查 `radialR` 是否真的被调用 |
| 径向节面位置偏了 | 拉盖尔递推系数写错 | `--dump-cloud 3s` 应为 1.90 / 7.10 |
| 接受率掉到 1/13 | `AngularProbe::maxSquared` 从 1.0 起扫 | 初值必须 0.0 |
| 云整个看不见 | `r98` 为 0（轨道非法）或 `model` 缩放为 0 | `validOrbital` 先挡住非法组合 |
| 视角一转云就"漂" | 忘了乘 `g_spinMatrix` | 和轨道形状一样跟自动旋转 |
| 换了轨道还是旧形状 | 只改了 state，没触发重采样 | 比对四个标量后调 `setupCloudPoints()` |

## 九、遗留

1. **没有 f 轨道**（l = 3）。`n ≥ 4` 的 f 轨道需要 7 个实球谐，且 5–7 周期的
   填充要等 f 区布局一起做。
2. **点云全在分子中心**，不跟随单个原子。跟随需要「选原子 → 选轨道」的交互设计。
3. **没有径向的 LOD**：`6s` 的 r98 是 `1s` 的 22 倍，分辨率固定，
   远处的壳层会有摩尔纹。
4. **相位重叠会混色**：沿某个轴看过去时，前后两瓣投在同一片像素上，
   红 + 蓝 = 紫。这是体积渲染的固有现象，转个角度就分开了。
5. **没有相对论修正 / 屏蔽效应**：`R_nl` 是 Z = 1 的氢样函数，
   多电子原子的「能级交错」只体现在能级图（Day 17）里，不在点云里。

## 十、今日功能的变化与修改

### 10.1 多出来的能力

**按 `C` 打开电子云面板**，选主量子数 `n`（1–6）和角向部分（s / p / d），
就能看到这个轨道**真实的概率分布**。

- 昨天：`2s` 是一个球，`3s` 也是一个球 —— 因为它们只有角向部分。
- 今天：`2s` 是「一个密实的核心 + 中间一圈空 + 外面一层壳」，
  `3s` 是三层，`6s` 是六层。层数正好是 `n − l + 1`。
- 点按 `ψ` 的符号染色：`3s` 的三层是红-蓝-红交替，节面自己就是颜色分界。
- 点数、点径、不透明度三个滑杆可调；`Resample` 换一套随机点
  （固定种子保证同一套参数在同一台机器上永远长一样）。

### 10.2 行为变化（老用法会不会被影响）

| 场景 | 第 19 天 | 第 20 天 |
|---|---|---|
| 启动后的默认画面 | 只显示分子 | **一样**（电子云默认关闭） |
| 按 `O` | 显示轨道形状 | 一样 |
| 按 `C` | 无 | 显示电子云 |
| 轨道形状 + 电子云同时开 | — | 允许，云在下、壳在上 |
| 隐藏分子 | 只看 `O` 的状态 | 任一功能要求隐藏就隐藏；拾取与标签同步关 |
| `--dump` / `--dump-table` / `--dump-levels` / `--dump-orbital` | 正常 | 输出完全没变 |
| `--version` | v0.2.1 | v0.2.2 |

唯一的**行为变化**是"隐藏分子"的判定从「只看轨道形状」变成「轨道形状或电子云」。
这修掉了上一版的一个隐含 bug：如果将来有第二个功能也想隐藏分子，
原来的写法必然会出现「画面里没有原子、却能点中它」的不一致状态。

### 10.3 命令行变化

新增：

```bash
--dump-cloud            # 一组默认轨道的摘要表（8 个轨道 × 20000 点）
--dump-cloud 3dz2       # 单个轨道：统计 + 一维径向剖面 + 二维 ASCII 剖面
```

- 写法是「主量子数 + 形状」，`4p_x` / `4px` / `4pX` 都认（形状部分沿用第 19 天的容错解析）。
- 给了不存在的组合（`2d`、`1p`、`4f`、`7s`）会报错并列出约束，**不会**默默打摘要表。
- 帮助里 `--dump-orbital` 的用法说明顺手修正了：第 19 天扩到 9 个形状后，
  这里还写着 `[s|px|py|pz]`。

### 10.4 顺带修掉的问题

- **隐藏分子的判定统一成一个函数** `moleculeHiddenForOrbitals()`，
  拾取、标签、不透明渲染三处共用。
- **`--help` 里的形状列表过时**（见上）。

### 10.5 这个版本还不行的地方

- 没有 f 轨道；点云固定在分子中心，不跟随单个原子。
- 尺寸按 r98 归一，所以「看起来一样大」不代表一样大 —— 真实半径在面板上以 a₀ 显示。
- 沿轴观察时前后两瓣会混成紫色（体积渲染的固有现象）。
- 窗口里的实际观感尚未在真实 GPU 上验证。
