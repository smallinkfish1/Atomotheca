# 第 17 天 · 2D 能级图（使用说明）

> Atomotheca 模块第 3 天。前一天：元素周期表面板（Day 16）。

## 一、今日目标

给选中的元素画一张**能级图**：亚层按能量从下往上排，每个亚层画出它的轨道方框，方框里按洪特规则摆 ↑↓ 箭头。

验收标准只有一条，也是这张图存在的理由：

> **4s 必须画在 3d 下面。**

如果 4s 跑到 3d 上面，图就不再是"能级图"，只是一张排布式换个样子。

## 二、核心概念

### 1. 能级图的纵轴没有刻度

它不表示"多少电子伏特"，只表示**谁先填**。所以：

- 相邻两行的间距是固定的，不代表能量差；
- 同一个 `n+l` 的亚层（3d、4p、5s）现实里能量接近，图里仍然等距排列 —— 我们只需要次序对。

这不是偷懒。一旦画了刻度，就得给每个元素一套真实的能量值（还要考虑屏蔽效应随 Z 变化），那是量子化学计算，不是这个项目的范围。

### 2. 4s 与 3d 的关系是"填充时"的，不是"最终"的

这是最容易讲错的一处，也是能级图最容易被误解的地方。

- 对 **K、Ca**（Z=19、20），4s 确实比 3d 能量低 → 电子先填 4s。
- 对 **Sc 之后**（Z≥21），核电荷增加让 3d 被拉得更低，**3d 反而比 4s 低**。

所以严格说，"4s 在 3d 下面"只对填充次序成立。好消息是：**填充次序才是我们要教的东西**，而这张图画的正是填充次序。这也正好解释了 Fe²⁺ 为什么是 `3d⁶` 而不是 `3d⁴4s²` —— 4s 上的电子先走。

### 3. 洪特规则决定方框里怎么摆

同一个亚层里，电子**先各自占一个轨道、自旋平行**，占满了才开始配对。

- 2p³（N）→ 三个框各一个 ↑，没有成对的
- 2p⁴（O）→ 一个框 ↑↓，两个框 ↑

原因不是"电子不喜欢待在一起"这么简单：平行自旋的电子交换能更低、平均距离更远，整体能量更低。这条规则没有解析证明，是实验总结出来的经验规律（和 Cr、Cu 的例外属同一类现象）。

### 为什么能级图不自己记「看哪个元素」

能级图需要知道「现在看哪个元素的哪个离子」，但这件事周期表面板已经记着了（`selectedZ` / `ionIndex`）。

两种做法：

- ❌ 能级图自己再存一份 `selectedZ`，然后想办法和周期表同步
- ✅ 只有一个来源（`g_periodic`），能级图每帧被动接收

选后者。两个面板各存一份"当前选择"，一定会出现「周期表显示 Fe³⁺、能级图显示 Fe²⁺」的状态 —— 而且只在某些操作顺序下出现，最难查。

于是产生一个小设计：`ionIndex` 是面板内部的下标（0 = 中性，1..n 对应 `commonIonCharges`），不应该让 main.cpp 去解。所以给它加了个方法：

```cpp
int charge = g_periodic.selectedCharge(*current);   // 0 / +2 / +3
```

## 四、代码实现

### 4.1 电子分布只用两个数字

直觉写法是给每个轨道存"住着 0/1/2 个电子"，需要一个 `vector`。但洪特规则让分布变成唯一确定的：

```
n 个电子铺进 k 个轨道：
  paired = max(0, n - k)        // 有几个轨道成对
  single = n - 2 * paired       // 其余每个轨道一个
```

验算：

| 亚层 | n | k | paired | single | 画面 |
|---|---|---|---|---|---|
| 2p³ | 3 | 3 | 0 | 3 | `[↑][↑][↑]` |
| 2p⁴ | 4 | 3 | 1 | 2 | `[↑↓][↑][↑]` |
| 3d⁶ | 6 | 5 | 1 | 4 | `[↑↓][↑][↑][↑][↑]` |
| 3d¹⁰ | 10 | 5 | 5 | 0 | 全成对 |

所以 `LevelRow` 里只有 `paired` / `single` 两个 int，没有 vector。行内也不存在"哪个轨道成对"的选择 —— 五个 d 轨道是简并的，画哪个都等价。

### 4.2 缓存：不要每帧重建

能级行只依赖「元素 + 电荷」，和帧号无关。但绘制函数每帧都会被调用，天真的写法是每帧 `makeIon()` + 排序，等于每秒白白分配 60 次 vector。

```cpp
void EnergyDiagramState::refresh(const orbital::Element& e, int charge)
{
    if (cachedZ == e.atomicNumber && cachedCharge == charge)
        return;                    // 没变，直接走
    cachedZ = e.atomicNumber;
    cachedCharge = charge;
    // ... 重建 rows
}
```

这正是技术债里「`element.cpp` 按值返回 `vector`，Day 17 每帧画图时改为缓存」那一条的落地方案。注意我没有改数据层的接口 —— 缓存放 UI 状态里，数据层仍然是无状态、可随便调的，这个边界不能破。

### 4.3 一块画布 + 坐标反算，而不是 70 个控件

图上最多 9 行 × 5 个框 ≈ 45 个方框。每个都做一个 `InvisibleButton` 的话：

- 要保证 45 个 ID 唯一（Day 16 已经踩过这个坑）；
- 每帧 45 次布局计算，只为了一句 tooltip。

改成**整块区域一个 `InvisibleButton`**，鼠标落在哪一行靠坐标反算：

```cpp
ImGui::InvisibleButton("##canvas", ImVec2(contentW, rowCount * kRowH));
const int fromTop  = (int)((mouse.y - canvasPos.y) / kRowH);
const int hoverRow = rowCount - 1 - fromTop;   // rows[0] 画在最下面，所以倒过来
```

行高固定，这个除法就是精确的 —— 没有"缝隙里算不出来"的问题。

### 4.4 箭头不用字符画

```cpp
drawArrow(dl, base, height, color, up);   // 一根竖线 + 顶端三角形
```

**为什么不用 `"↑"`**：ImGui 默认字体是 ProggyClean，只有 ASCII 0x20–0xFF。U+2191 不在里面，会渲染成一个空方块 —— 和中文名显示成 `??` 是同一个原因。

### 4.5 「下一个填这里」的空层：我第一版写错了

第一版的做法是：沿 Madelung 序列走，遇到第一个「数据里没有的层」就补一个空框。结果：

```
Fe   3d 6/10
     4p 0/6   ← (next to fill)
```

**这是化学错误**。Fe 的 3d 才填了 6 个，下一个电子仍然进 3d，4p 要等 3d 满了才轮到。

正确规则：**只有所有已占据亚层都满了，才补下一个空层**。修正后：

| 元素 | 修正前 | 修正后 | 是否正确 |
|---|---|---|---|
| Fe | 补空的 4p | 不补（3d 未满） | ✅ 下一个电子进 3d |
| Ca | 补空的 3d | 补空的 3d（4s 已满） | ✅ 下一个电子进 3d |
| H⁺ | 补空的 2s | 不补（1s 是 0/2，下一个填 1s） | ✅ |
| Kr | 补空的 5s | 补空的 5s | ✅ |

这个错误如果没被 `--dump-levels` 打出来，会一路进到界面，而且看起来完全正常 —— 空框谁也不会怀疑。

## 六、排错清单

| 现象 | 原因 | 处理 |
|---|---|---|
| 4s 画在 3d 上面 | 用了书写顺序 `sortByShell` 而不是能量顺序 | 图里只能按 `sortByEnergy` / Madelung 序列排 |
| 3d⁶ 画成 3 对 | 按"先配对"填的 | 洪特规则：前 `min(n,k)` 个轨道单占，剩下才配对 |
| 出现空的 4p 占位但 3d 没满 | 占位条件写成「第一个缺失的层」 | 必须「所有已占据亚层都满」才补下一层 |
| 箭头显示成方块 | 用了 `"↑"` 字符 | ImGui 默认字体无此字形，必须用 DrawList 画 |
| 点一行亮的是另一行 | 用了逐框 `InvisibleButton` 且 ID 重复 | 整块画布一个按钮，行号靠坐标反算 |
| 切元素时窗口高度跳动 | 用 `ImGuiCond_Always` 设了窗口尺寸 | 首次设定用 `ImGuiCond_FirstUseEver`，高度自适应 |
| 图例文字被切掉一半 | 窗口宽度没算足，`TextDisabled` 不折行 | 左侧标签 + 5 个框 + 计数列，宽度留够（本处 80px） |
| 能级图和周期表显示不同元素 | 各自存了一份 `selectedZ` | 只保留周期表一份，能级图每帧接收 |
