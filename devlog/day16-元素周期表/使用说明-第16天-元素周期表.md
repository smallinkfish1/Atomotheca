## 二、核心概念

### 1. 周期表不是列表，是二维坐标

第 15 天的数据层已经给每个元素存了 `period`（第几行）和 `group`（第几列，1–18）。所以画表不需要"按顺序一个个摆"，只要把每个元素放到 `(period, group)` 这个坐标上。

```
for period in 1..4:
    for group in 1..18:
        element = 找(period, group)
        画格子(element)
```

对比一下错误做法——按数组顺序流式排（一行放 18 个，满了换行）：

| | 坐标定位 | 顺序流式 |
|---|---|---|
| H 与 He 之间 | 中间留 16 个空格（正确） | 紧挨着（错） |
| 缺一个元素 | 只缺那一格 | 后面全体左移一位 |
| 加新元素 | 改一行数据 | 顺序变、位置全乱 |

**结论**：布局由数据里的坐标决定，不由数组下标决定。这一条决定了整个实现方式。

### 2. 为什么第 2、3 周期中间是空的

18 族 = 1s(2) + 2s(2) + 2p(6) + 3s(2) + 3p(6) 的容量拼起来：

- 第 1 周期：只有 1s → 2 个元素（H、He），He 放在第 18 族（它不是"第 2 族"）
- 第 2、3 周期：s 区 2 列 + p 区 6 列 = 8 个元素，中间的 3–12 族（d 区）**这一层根本没有 d 轨道**，所以不存在
- 第 4 周期起：4s 填完后开始填 3d，才有 10 个过渡金属把 3–12 族填满

所以代码里要区分两种"没有元素"：

```cpp
// 位置本身不存在（第 2 周期的 3–12 族）→ 留白
// 位置存在但数据库没收录 → 画淡框，提示 not in database
//（第 4 周期现已补满，这个分支等扩到 5–7 周期才会再用到）
bool cellExists(int period, int group) {
    if (period == 1) return group == 1 || group == 18;
    if (period <= 3) return group <= 2 || group >= 13;
    return true;
}
```

### 3. ImGui 是"立即模式"：没有控件对象，只有每帧重画

传统 GUI（Qt）里，按钮是个对象，创建一次、存在内存里、等它被点击。

ImGui 反过来：**每帧从头跑一遍绘制函数**，`if (ImGui::Button("OK"))` 每帧都执行一次，返回"这一帧它被点了吗"。

由此带来两个直接后果：

1. **状态必须自己存**。按钮记不住"我上次是选中的"，所以选中项放在 `PeriodicTableState` 里跨帧保存。
2. **控件要有唯一 ID**。ImGui 用 ID 判断"这帧的按钮"是不是"上帧的按钮"，用来做 hover、点击、动画。同一个窗口里 72 个格子如果都叫 `"##cell"`，它们就是同一个 ID —— 点第一格可能点亮第三格。

解决办法是 ID 栈：

```cpp
ImGui::PushID(el->atomicNumber);   // 把原子序数压进 ID
ImGui::InvisibleButton("##cell", size);   // 真实 ID = 26/##cell
ImGui::PopID();
```

### 为什么单独开 `src/ui/` 而不是塞进 main.cpp

`main.cpp` 已经 1502 行，再往里加 300 行会变成"什么都往里塞"的地方。更关键的是依赖方向：

```
main.cpp  →  ui/periodic_table  →  orbital/element
   ↓                ↓
 OpenGL          ImGui
```

`ui/` 只依赖 ImGui 和纯数据层，**不 include glad**。好处是第 20 天再想把 UI 拆出去时，这个文件直接搬走就行；也让"化学数据算错"和"界面画错"这两类问题有清晰的边界。

### 面板状态为什么单独一个结构体

```cpp
struct PeriodicTableState {
    bool visible   = true;
    int  selectedZ = 8;    // 默认氧，和 --dump 的示例一致
    int  ionIndex  = 0;    // 0 = 中性
};
```

不并进 `UiState` 的理由：`UiState` 里是"分子怎么显示"（半径、光照、背景），周期表是另一块业务的选中态。混在一起，第 20 天拆分时又要重新分辨谁是谁。

### 4.2 `src/ui/periodic_table.cpp`（新建，核心部分）

**网格参数**（`kGroups / kCellW / kCellH / kCellGap / kLabelCol`）：18 列固定，行数取数据里最大周期。

**格子自绘**：不用 `ImGui::Button`，因为它只能显示一行文字、没法同时画"原子序数 + 符号"两行。改用 `InvisibleButton` 占位 + `DrawList` 手画：

```cpp
ImGui::PushID(el->atomicNumber);
ImGui::InvisibleButton("##cell", ImVec2(kCellW, kCellH));

const ImVec2 a = ImGui::GetItemRectMin();      // 刚刚占位出来的矩形
const ImVec2 b = ImGui::GetItemRectMax();

if (ImGui::IsItemClicked()) {
    state.selectedZ = el->atomicNumber;
    state.ionIndex  = 0;                        // 换元素时回到中性
}

dl->AddRectFilled(a, b, ImGui::GetColorU32(ImVec4(c[0], c[1], c[2], alpha)), 3.0f);
dl->AddRect(a, b, border, 3.0f, 0, isSel ? 2.0f : 1.0f);

dl->AddText(ImVec2(a.x + 3.0f, a.y + 1.0f), ink, zText);            // 第一行：Z
dl->AddText(ImVec2(a.x + (kCellW - ts.x) * 0.5f, a.y + 15.0f), ink, // 第二行：符号居中
            el->symbol.c_str());

ImGui::PopID();
```

**文字颜色按底色亮度反转**：

```cpp
ImU32 inkOn(const std::array<float, 3>& c)
{
    const float lum = 0.299f * c[0] + 0.587f * c[1] + 0.114f * c[2];
    return (lum > 0.55f) ? IM_COL32(20, 20, 26, 255)      // 浅底 → 黑字
                         : IM_COL32(245, 245, 250, 255);  // 深底 → 白字
}
```

不加这一步，H（CPK 白色）和 He（浅黄）格子上的符号会看不见。

**离子切换**：第 0 个按钮是中性的，后面按 `commonIonCharges` 顺序生成：

```cpp
for (int i = 0; i <= ionCount; ++i) {
    if (i > 0) ImGui::SameLine();
    const std::string label = (i == 0) ? std::string("Atom")
                                       : ionLabel(*sel, sel->commonIonCharges[i - 1]);
    ImGui::RadioButton(label.c_str(), &state.ionIndex, i);
}
```

按钮文字用的 `ionLabel()` 是本地小函数（`Fe2+` / `O2-` / `H+`），规则和 `orbital::Ion::label()` 一致，但不必为了一行按钮文字去构造整个离子排布。

选中离子后才调 `makeIon()` 算排布：

```cpp
const orbital::Ion ion = sel->makeIon(sel->commonIonCharges[state.ionIndex - 1]);
ImGui::Text("electrons %d    charge %+d", ion.electronCount(), ion.charge);
ImGui::TextWrapped("%s", ion.configString().c_str());
```

**中性状态额外显示"填充次序"**（和书写顺序不同时才打）：

```
config     1s2 2s2 2p6 3s2 3p6 3d6 4s2
fill order 1s2 2s2 2p6 3s2 3p6 4s2 3d6
```

这一行是为了第 17 天画能级图打底——读者要先接受"4s 比 3d 先填"这个反直觉事实。

## 六、排错清单

| 现象 | 原因 | 处理 |
|---|---|---|
| 点一格，亮的是另一格 | 格子没 `PushID`，72 个 `InvisibleButton` 共用一个 ID | 用原子序数做 ID：`PushID(el->atomicNumber)` |
| 格子有底色但看不见符号 | H、He 这类浅色底 + 白色文字 | 按亮度反转字色，见 `inkOn()` |
| 第 2/3 周期中间被填满或整体错位 | 用了顺序流式排列，没按 `(period, group)` 定位 | 布局由坐标决定，不由数组下标决定 |
| 所有格子挤在左上角 | `SameLine` 的 offset 用了相对上一个控件而非行首 | 每行第一格 `SameLine(kLabelCol, 0)` 固定列宽，其余用 `SameLine(0, kCellGap)` |
| 第 4 周期出现淡框 | 数据只到 21 个元素时是这样（历史的中间状态） | 补数据后第 4 周期 18 格全满；淡框只剩 5–7 周期会用 |
| 面板打开但一片空白 | `elements.json` 没找到，`db.empty()` 走了提示分支 | 看启动日志的"元素数据库"那行；从 `build/` 里运行也能找到（三级回退） |
| 中文名显示成 `??` | ImGui 默认字体没有中文字形 | 面板标签全用英文；要中文得加载字体文件，见技术债 |

## 九、遗留

1. **窗口效果未实机验证** —— 需要你在真实桌面确认，重点看四件事：族号是否和列对齐、格子是否对齐、浅色元素符号是否看得清、点击是否选中正确的格子。
2. **5–7 周期未收录** —— 数据库到 Kr（Z=36）为止。往后再扩要处理 f 区：镧系锕系在标准表里是「挖出来单列两行」的，`(period, group)` 二元坐标表达不了，得先设计布局规则。
3. **族号是纯数字 1–18** —— IUPAC 有 1–18 的现代编号，也有 IA–VIIIA / IB–VIIB 的旧编号。面板只画前者，没做切换。
4. **元素中文名没显示** —— 数据里有 `nameZh`，但字体没有中文字形。要么加载中文字体（要改 `path_utils.h`），要么保持英文。

## 十、补丁记录（同日追加）

第一次交付后按你的要求补了两件事：**把剩下的元素补全**、**加族号**。

### 10.1 数据：21 → 36 个元素

补了 15 个：Sc(21) Ti(22) V(23) Cr(24) Mn(25) Co(27) Ni(28) Cu(29) Zn(30) Ga(31) Ge(32) As(33) Se(34) Br(35) Kr(36)。加上原有的 Fe(26)，第 4 周期 18 个族齐了，Z 从 1 到 36 连续无缺口。

关键的两处**不能用 Madelung 规则算**：

| 元素 | 规则会给出 | 实际（洪特规则 + 半满/全满稳定性） | 写进 JSON 的 |
|---|---|---|---|
| Cr (24) | `3d4 4s2` | `3d5 4s1`（d 半满更稳定） | `3d5 4s1` |
| Cu (29) | `3d9 4s2` | `3d10 4s1`（d 全满更稳定） | `3d10 4s1` |

所以数据层不改一行代码：JSON 里存的就是权威排布，`element.cpp` 只负责校验「电子总数 = Z」和「按先失最外层推离子」。这是刻意设计——**规则用来算离子和排序，不用来覆盖数据**。真按规则重算，这两个元素会被"修正"成错的。

离子推算的连带验证（全对）：

```
Cr3+ → 3d3      先失 4s1，再失两个 3d     （化学上 Cr3+ 就是 3d3）
Cu+  → 3d10     只失 4s1，d 层保持全满
As3- → 4p6      阴离子按能级填，正好补满 4p
Se6+ → 3d10     4p、4s 共 6 个电子全失，剩 3d10
```

### 10.2 族号表头

在网格上方加一行 1–18。看起来只是多画 18 个数字，实际有个对齐问题：

```cpp
const float headerH = std::max(kHeaderH, ImGui::GetTextLineHeight());  // 跟着字体/DPI 走

// 行首 1px 的 Dummy 是必须的：SameLine() 需要一个「上一格」才能定位
ImGui::Dummy(ImVec2(1.0f, headerH));
for (int g = 1; g <= kGroups; ++g)
{
    if (g == 1) ImGui::SameLine(kLabelCol, 0.0f);   // 和周期号列同宽
    else        ImGui::SameLine(0.0f, kCellGap);    // 和格子同间距

    ImGui::Dummy(ImVec2(kCellW, headerH));           // 占出与格子等宽的矩形
    const ImVec2 a = ImGui::GetItemRectMin();
    const ImVec2 b = ImGui::GetItemRectMax();
    // 在矩形正中 AddText，而不是塞一个 ImGui::Text
    dl->AddText(ImVec2((a.x + b.x - ts.x) * 0.5f, a.y + (headerH - ts.y) * 0.5f),
                headerInk, gText);
}
```

三个坑：

1. **不能用 `ImGui::Text` 画数字**。`Text` 的对齐由字体行高和 `ItemSpacing` 决定，和 34px 的格子步进对不上，最后几列会越错越远。用 `Dummy` 占出和格子完全相同的矩形，再在矩形里 `AddText`，坐标就必然一致。
2. **`SameLine()` 必须有前置 item**。它靠 `CursorPosPrevLine` 取 y 坐标，行首什么都不放会定位到上一行。所以第一列前面塞一个 1px 宽的 `Dummy`。
3. **表头高度不能等于格高**。14px 的高度让表头看起来像标题而不是可以点的格子；如果做成 34px，用户会去点族号。同时高度取 `max(14, 字体行高)` —— 写死像素在换字体或 HiDPI 缩放下会把字挤出格子。

顺带在网格底部加了一行 `36 elements · periods 1-4`，用来一眼确认数据补到哪。
